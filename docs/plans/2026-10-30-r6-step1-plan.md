## Work items

1. **Shared fixture convention.** `tests/fixtures/providers/<provider>/<case>.json`.
   Each file carries a provenance header: `source` (`docs-derived` or
   `recorded-live`), the API version or documentation URL, the capture date, and
   a redaction note. A small loader serves them through
   `plm_platform.testing.http.MockHTTP`. A conformance test runs one scenario
   list against the mock client and against the real client on replayed
   responses, and asserts both give the same contract output.
2. **Injectable transport.** Add an optional `client: httpx.Client` (or a
   factory) to `SunoClient`, `RealYouTubeClient` and
   `RealYouTubeAnalyticsClient`, and stop the YouTube constructor reading `.env`
   when settings are passed in. Behaviour is unchanged when nothing is injected.
3. **Conformance suites**, one adapter per commit, in this order (from most
   ready to least):
   - P9 Reporting: report-type catalog, job list, CSV download, 401/403/404.
   - P9 Analytics: metrics, retention, traffic sources, quota error bodies.
   - P7 YouTube: OAuth refresh, resumable upload (308/Range resume, final 200),
     `videos.update`, thumbnails, quota and `uploadLimitExceeded` errors. Every
     write path asserts it is reachable only through `ExternalWriteGuard`.
   - P4 Suno: generate, poll (all states), billing/credits, download, the
     `/download/authorize` fallback (consumes allowance), 402/429.
   - P1 Spotify/Trends: auth, batching, 401/429; wire the unused fixture.
4. **P8 distributor: out of scope.** The owner is not using a music
   distributor because of the cost (2026-10-30). There is no distributor client
   to build or test, so P8, UPC and P20 stay on the mock.
5. **Gate R6-1.** CI green on the pushed revision with the P1, P4, P7 and P9 suites. No
   credential is present in CI. STATUS rows are updated per adapter with what
   the replay proves (the response shape we handle) and what it doesn't (that
   the provider still answers that way).
